# Audit Tier-2 + backlog orchestration plan

This file hands off the remaining findings from a whole-codebase audit whose
Tier-1 cleanup already merged as **PR #684**. It is meant to be read by a fresh
Claude Code session (Fable is fine). Everything needed is here — do not assume
prior conversation context.

## Ground rules (apply to every change)

- **Verify before you touch.** The tree has moved since the audit — some findings
  are already fixed (e.g. the S4 `server_lifecycle.gd:112` worker-thread item was
  fixed by #683; the whole doc/comment/dead-code drift set was fixed by #684).
  Re-derive each finding against current code FIRST; if it's resolved, note that
  and skip it. Never blindly re-implement.
- **One theme per PR**, ready-for-review, off the latest `origin/main`. Do NOT
  bundle unrelated fixes. Do NOT reopen or reuse #684 (merged).
- **Deletions and tightening only** — no refactors for taste, no idiom
  modernization, no diff that adds more complexity than it removes.
- **Never delete a published `class_name`** (self-update compat policy; see
  AGENTS.md "Published class_name compatibility"). Broken shims get fixed, not
  removed.
- **Every code fix needs tests** — Python in `tests/`, GDScript in
  `test_project/tests/`.

## The gauntlet (run fully before EVERY commit; paste results in the PR)

1. `ruff check src/ tests/`
2. `pytest -q`  — first `pkill -f 'python -m godot_ai'` so port 8000 is free, or
   the `test_cli_reload` bind tests flake with "address already in use".
3. `bash script/ci-check-gdscript`
4. Live editor test (0 failed required):
   - `bash script/ci-start-server .venv/bin/python`
   - `GODOT_AI_ALLOW_HEADLESS=1 godot --headless --path test_project --editor &`
   - `bash script/ci-godot-tests`
5. If the change touches server lifecycle / spawn / kill / self-update, also run
   BOTH: `.venv/bin/python script/ci-stale-server-smoke --log-dir /tmp/smoke` and
   `… --mode foreign --log-dir /tmp/smoke`; and for self-update,
   `script/local-self-update-smoke`.
6. Before committing: `git checkout -- test_project/project.godot` (drops the
   editor's 4.6/4.7 churn — never stage it).

## Setup (once per fresh container)

`script/setup-dev` then `source .venv/bin/activate`. Confirm baseline green
(steps 1–3) before starting.

## Order of work

**Phase 1 — the 7 filed issues (#685–#691), sequential, one PR each.** Highest
value; do these first. Order: #685 (S4) → #689 → #687 → #688 → #686 → #691 → #690.
Details + evidence are in each GitHub issue body — read it before starting.

**STOP AND ASK the maintainer before implementing these design decisions:**
- #687 release **signing** (ed25519/minisign + key management) — infra decision.
- #690 handshake **auth token** — protocol/compat change.
- #688 the Godot **4.5-vs-4.6 version-gate** for the non-finite-float clamp.
- #685 **overwrite semantics** — hard-error vs an `overwrite=true` param.

**Phase 2 — the backlog below.** After the 7 issues, work the Tier-1 backlog by
batching related items into a few themed PRs (e.g. "test-honesty round 2",
"dup: consolidate the JSON→Color / property-error / manual-command copies",
"remaining safe dead-code deletion", "port-probe copy consolidation"). File a
new GitHub issue for each Tier-2 backlog item (or fold into #685–#691 where it
fits). For report-only items: verify, fix if trivial, else note in an issue.

Same gauntlet, same one-theme-per-PR discipline, same verify-first rule, same
ask-before-design-calls rule throughout.
